02What isn't native to Frappe

Two clusters of custom build: the security isolation between field staff, and the reverse-reporting telemetry feeding project health.

Core to the security & permission model

  • Lateral Field Officer isolation — standard Frappe role permissions grant all users with the "Field Officer" role edit access to all records. We enforce strict lateral isolation in has_feedback_survey_permission and enforce_feedback_survey_least_privilege: Field Officers can edit only their own surveys; peers are blocked.
  • Hierarchical downward oversight — Project Managers and Coordinators only have write access to surveys attached to projects assigned to them, while Director and CEO hold org-wide authority.
  • Submittable record locking — once submitted (docstatus: 1), ground observations cannot be silently altered; changes require a formal Frappe amendment (amended_from).

From the field operations engine

  • Dual quantitative & qualitative capture — captures numeric adoption percentages, participant counts, and household numbers alongside narrative "Significant Change" stories and direct community quotes.
  • Multi-step mobile wizard — clean web wizard at /feedback_survey allowing low-friction survey entry on mobile devices with offline-friendly validation.
  • Auto-aggregation on KV Project — linked surveys automatically roll up into the feedback_surveys child table on KV Project, recomputing the project's overall rating and journey stage.
  • Real-time WhatsApp event dispatch — instant WhatsApp notification sent via Meta Cloud API to the Project Manager and Coordinator when a survey is submitted from the field.

04Roles involved

Field Officer (Collector)

Conducts field visits, interviews farmers and SHG members, inputs quantitative adoption metrics, records community voices, and submits the survey.

Project Manager / Coordinator

Receives WhatsApp and in-app alerts on submission, validates facilitator observations against activity goals, and marks records as Reviewed.

Director / CEO / System

System locks peer access and routes notifications. Leadership inspects qualitative quotes, ratings, and adoption trends on executive dashboards.

07Observations worth flagging

  • Strict Lateral Isolation Active — Unlike default Frappe permissions where all Field Officers can edit each other's work, krushi_vikas.api.enforce_feedback_survey_least_privilege strictly blocks peer Field Officers from modifying surveys they did not conduct.
  • Submittable Document Security — is_submittable: 1 is enabled. Once submitted, ground data is sealed into the system audit trail; any modification must be made via standard amendment.
  • Direct KV Project Rollup — When a Feedback Survey is linked to a KV Project, the project automatically displays it in its feedback_surveys child table, recalculating project-level reverse reporting milestones.
  • Instant WhatsApp Event Dispatch — On submission, the system triggers real-time WhatsApp alerts and in-app Notification Logs to the assigned Project Manager and Project Coordinator.
  • Dual-Channel Access — Field teams can enter data directly in Frappe Desk or use the mobile-optimized Web Wizard at /feedback_survey without exposing backend administrative views.
