02What isn't native to Frappe

Two clusters of custom build: the mechanics underneath every stage, and the specific objects the feature list calls for.

Core to the domain model

  • KRE / OKR tracking — no native object with baseline / current / target / stretch and planned-vs-actual math. Called out as the heart of the app.
  • Hard dependency gating — depends_on on Task is advisory only; it won't block a task from completing until its predecessor finishes. Needs a custom validate hook.
  • Tiered SLA escalation — the blocked → PC → PM → Director climb-on-repeat-breach doesn't exist natively; it's a custom scheduled job walking the Reports-To chain.

From the feature-list deep dive

  • Survey engine — no native RRA / baseline / endline templating with selectable question sets and media capture.
  • Activity- and user-level budget % — native ERPNext Budget is account/cost-center scoped, not per-task or per-user.
  • Goal → Objective → KRE weighted rollup — no native OKR-style weighted hierarchy that sums to 100% and rolls up.
  • Concept Note → Project spawning — a Concept Note must exist before a Project can be created; this will be mandated.
  • Baseline-vs-endline delta reporting — the diff/comparison analytics across two survey rounds is custom.

04Roles involved

Creator

Fills in the Concept Note and submits it for approval. Can be anyone with access to the form.

Approver

Named on the note itself. Only this specific person can approve or reject it — not just anyone holding an approver role.

System

Sends the notification email the moment a note is submitted, and keeps the record of who did what and when.

05Step-by-step walkthrough

Creator fills out the Concept Note who: creator

Title, description and expected benefits are entered, and the intended Approver is selected from a list of eligible people. The Creator's own name and email fill in automatically — nothing to type there.

Concept Note form, new record
Creator submits for approval who: creator

A single click moves the note from Draft to Pending Approval. Nothing is sent for approval until the Creator chooses to submit it.

Workflow action button, top-right of the form
Approver is notified automatically who: system

The moment the note reaches Pending Approval, an email goes out to the named Approver with the title, who raised it, and a direct link straight to the record — no searching for it.

Automatic email, triggered by the submit action
Approver approves or rejects who: role-based

The named Approver reviews the note from the link in the notification email and moves it to Approved or Rejected — the final, deliberate decision in the flow.

07Observations worth flagging

  • No attachment fields are defined on this DocType — if supporting documents (proposal PDFs, budget sheets) need to attach to a Concept Note, an Attach or Attach Image field has to be added.
  • The DocType is submittable (is_submittable: 1), so once submitted, most fields would typically lock unless explicitly made editable post-submit — worth confirming which fields should stay editable after submission.
  • track_changes: 1 is enabled, so field-level edit history is visible in the document's timeline automatically — no separate "commentary" field is needed for that.
