How a Project Moves Through Krushi Vikas

An idea becomes a funded, staffed, monitored, and evaluated agricultural program through ten deterministic stages — complete role boundaries, hard gates, lateral security, and real-time reverse reporting telemetry.

02The Four Core Phases

The platform groups the 10 operational steps into four discrete governance phases:

Phase 1 · Planning & Conception

Donor Alignment & Rural Appraisal

Steps 01 – 02. External funding proposals or internal initiatives are conceived, reviewed by leadership, and vetted against Rapid Rural Appraisal (RRA) assessments. Held as reference data; no operational expenditure is unlocked yet.

Phase 2 · Formalization & Baseline

Maker-Checker & Ground Truth

Steps 03 – 05. The Project Manager builds the operational budget and project proposal. Leadership formally signs off, and Field Officers capture baseline indicators and village media before any intervention commences.

Phase 3 · System Ingestion & Control

Project Creation & Task Allocation

Steps 06 – 08. The Project Coordinator creates the live KV Project from the approved proposal. An internal approval gate ensures compliance, after which the Project Manager assigns activities and tasks to designated Field Officers.

Phase 4 · Field Actions & Telemetry

Execution & Reverse Reporting

Steps 09 – 10. Field officers execute tasks, log expenditure, and conduct structured Feedback Surveys. Real-time Meta WhatsApp alerts push field updates to managers, rolling up directly into executive dashboards.

05The Hand-Offs & Code Gates

Transitions are whitelisted Python API functions in krushi_vikas/api.py that refuse to run out of order:

# 1. Spawn RRA Report from Approved Concept Note (02 <- 01)
create_rra_from_concept_note(concept_note)
# Guard: concept_note.status must == "Approved"

# 2. Spawn Proposal from Favourable RRA Assessment (03 <- 02)
create_proposal_from_rra(rra_report)
# Guard: rra_report.recommendation must == "Proceed"

# 3. Spawn KV Project from Approved Proposal (06 <- 04)
create_project_from_proposal(proposal, coordinator)
# Guard: proposal.workflow_state must == "Approved"
# Carries budget, dates, thematic areas, and manager across seamlessly

# 4. Roadmap Readout for Any Project
get_journey_status(project)
# Returns current stage, completion %, and next actionable gate

07Real-Time Telemetry & SLA Escalation Ladder

Two automated escalation mechanisms keep projects moving without manual policing:

Tiered SLA Escalation Job

  • Day 0 (Due Date): Bell notification + High-priority ToDo allocated to the assigned Field Officer.
  • Day 3 (First Breach): Escalates to Project Manager & Project Coordinator automatically.
  • Day 7 (Critical Breach): Escalates to Project Director and CEO.

Meta WhatsApp Cloud API Telemetry

  • Task Assignment: Real-time WhatsApp alert sent to officer's mobile when task is allocated.
  • Feedback Submission: Real-time WhatsApp notification sent to Project Manager and Coordinator the moment a Feedback Survey is submitted.
  • Webhook Events: Bi-directional receipt of delivery receipts (sent, delivered, read) and incoming officer messages.

08Step-by-Step Lifecycle Walkthrough

01 · Concept Note Conceived & Approved who: donor / pm → director

Initial idea submitted by donor or project manager with target geography, thematic area, estimated beneficiaries, and proposed budget. The Director signs off, setting status to Approved.

DocType: Concept Note • Action: Approve
02 · Rapid Rural Appraisal (RRA) Assessment who: management / appraisal team

Field market and community feasibility appraisal is conducted. If the assessment confirms village need and viability, recommendation is marked "Proceed", unblocking proposal creation.

DocType: RRA Report • Gate: recommendation = 'Proceed'
03 · Project Proposal & Budget Formulation who: project manager

The Project Manager drafts work packages, links Project Themes, establishes financial line items (Proposal Budget Lines), and schedules planned milestones.

DocType: Project Proposal • Status: Draft
04 · Executive Formal Proposal Approval who: project director / ceo

Senior executive formal sign-off. If approved, the proposal locks and permanently certifies the sanctioned budget and scope. If rejected, it returns to the PM with feedback.

DocType: Project Proposal • Workflow: Approved
05 · Ground Baseline Survey who: field officer

Before interventions start, field staff log household economic data, baseline crop yields, and village photos to establish the scientific control for post-project delta evaluations.

DocType: Baseline Survey / Survey Response
06 · Live KV Project Spawned who: project coordinator

Coordinator invokes create_project_from_proposal. Budget, timeline, thematic tagging, and manager links port over automatically with zero manual re-keying.

DocType: KV Project • API: create_project_from_proposal
07 · Internal Maker-Checker Sign-off who: project director / ceo

Internal operational gate. The Director verifies coordinator assignments and sanctions deployment. Moves project status to In Progress.

DocType: KV Project • Field: approval_status = 'Approved'
08 · Work Breakdown & Task Assignment who: project manager

Manager assigns Activities and granular Tasks to Field Officers. Automatic WhatsApp alerts ping officers with direct task deep-links and expected due dates.

DocType: Activity & Task • Alert: Meta WhatsApp Cloud API
09 · Field Execution & Predecessor Gating who: field officers

Officers execute soil treatments, sapling distribution, or farmer trainings. Hard dependency checks block dependent tasks until predecessor milestones are formally verified.

DocType: Task • Validate: depends_on check
10 · Reverse Reporting & Telemetry Rollup who: field officer → leadership

Field Officer submits qualitative success stories, farmer quotes, and adoption percentages via Feedback Survey. Peer officers are laterally isolated from tampering. Real-time WhatsApp alerts ping the PM and PC, and metrics roll into Executive Dashboards.

DocType: Feedback Survey • Rollup: KV Project feedback_surveys

10Architectural Observations & Best Practices

  • Zero Data Drifting — Critical variables (sanctioned budget, thematic tags, target villages) inherit programmatically from Step 01 to Step 06. Manual re-typing is strictly disabled.
  • Lateral Isolation Enforced at API Level — Permission checks do not rely on UI hiding. has_permission and validate hooks throw permission errors if peer officers or peer coordinators attempt to touch each other's records.
  • Hard Dependency Gating — Standard Frappe depends_on on Tasks is advisory. Krushi Vikas implements a custom validate hook that prevents a task from moving to Completed if predecessor tasks remain open.
  • Bidirectional WhatsApp Loop — Field workers do not need constant desktop access. Meta WhatsApp Cloud API pushes actionable deep-links for task allocations, overdue warnings, and survey submissions.
  • Monotonic State Progression — journey_stage on KV Project is derived dynamically from child activities and surveys, ensuring project progress can never be manually spoofed.
