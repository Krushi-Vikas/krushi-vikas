Field collection - user journey & design reference

How baseline and village data enter the system

Stage 5 of the platform journey, documented as two Desk forms: a household Baseline Survey and a Village Profile. Field Officers collect the benchmark data that Project Coordinators use when setting up the project.

02What is custom to Krushi Vikas

These records deliberately replace the generic Survey Response placeholder for the detailed, source-form-led baseline collection.

Household Baseline Survey

  • One document per household, identified by beneficiary_uid where a barcode or unique identifier is available.
  • Structured child tables preserve repeatable details such as household members, crops, water assets, livestock, loans, income and expenditure.
  • Calculated totals retain household-member, livestock, crop-profit and monthly-to-annual financial consistency.

Village Profile

  • One document per village, with an optional unique census or revenue code and device-captured GPS coordinates.
  • Separate child tables hold caste demographics, land use, cropping, water sources, facilities, public institutions and livestock.
  • Controller validation checks future dates, negative totals and counts that exceed the stated village household or population totals.

03The field collection flow, at a glance

There is no approval workflow for collection. A Field Officer saves work as Draft, then submits it when the source form is complete. Frappe submission locks the before-state record; the Coordinator can use it during project setup.

04Roles involved

Field Officer

Creates, completes and submits records filed under their own user account. Row-level access prevents an officer from opening a peer officer's submissions.

Coordinator / Manager

Reads records in their operational scope. Coordinators use field evidence as an input to project creation; neither role creates a field submission under the standard journey.

Director / CEO

Have organization-wide survey visibility. Submitted records remain the auditable before-state rather than an editable planning document.

07Observations worth flagging

  • The former public Village Profile wizard is retired in favour of authenticated Desk collection. This aligns field evidence with Frappe permissions and the documented Field Officer ownership model.
  • The existing generic Survey Template and Survey Response records remain relevant for configurable RRA and endline questionnaires. They are not the canonical storage for the fixed, detailed household and village source forms.
  • Before release, run migration and build assets, then test record creation, submission lock and row-level permissions with the named Field Officer, Coordinator, Manager, Director and CEO test accounts. Static metadata checks alone do not prove the Desk experience.
  • GPS format, socio-economic-score range and JSON payload validation should be enforced in the Baseline Survey controller before using those fields for eligibility or reporting decisions.
